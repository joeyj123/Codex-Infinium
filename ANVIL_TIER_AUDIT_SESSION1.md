# Anvil Challenge Tier Audit — Session 1

Read-only content audit of `data/knowledge_base.json`. No source data was modified.

## Summary

- Total novice `anvil_challenges` analyzed: **294** (across 42 of 57 novice topics)
- Mapped to **apprentice** tier: **280**
- Mapped to **journeyman** tier: **14**
- Mapped to **master** tier: **0**
- Mapped to **expert** tier: **0**
- Mapped to **legend** tier: **0**
- Unmapped / flagged (no clean home found anywhere): **0**

### Notable patterns

- The overwhelming majority of challenges (280/294) rest on fundamentals taught in **apprentice**: `variables_data_types` (assignment, string concatenation), `operators` (comparison/boolean logic), `conditionals` (if/elif/else), `loops` (for/while), `arrays_lists` (indexing, `.append()`, `len()`), `dictionaries_maps` (key-value access), `functions_scope` (def), and `survey_python` (list comprehensions).
- A smaller cluster (14/294) needs **journeyman**-level content specifically: `string_manipulation` (`.upper()`/`.lower()`/`.strip()`/`.split()`/`.join()`/slicing) and `type_casting` (`int()`/`str()`/`float()`), because apprentice's `variables_data_types` only introduces the concept of data types, not Python's specific string-method or casting syntax.
- **No challenges required master, expert, or legend tier concepts** — none of the 294 challenges exceed journeyman-level Python syntax (no classes, no recursion, no exception handling, no list comprehension beyond basic filter/map forms already covered at apprentice `survey_python`, no library imports).
- **f-string interpolation** (`f"...{var}..."`) appears in the solution code of 38 challenges, but **no topic in any tier explicitly teaches f-string syntax** — the KB discusses string data types and concatenation (`variables_data_types`) and string methods (`string_manipulation`), but never Python's f-string literal syntax itself. These challenges were mapped to their next-best concept (assignment/concatenation/output), with f-strings flagged as a content gap rather than blocking the mapping — see the note column in the table and the Flag List below.
- Zero challenges were fully unmappable — every challenge's dominant concept traces to an existing apprentice or journeyman topic.

## Methodology

1. Extracted all 294 novice `anvil_challenges` via script (not manual JSON reading).
2. For each challenge, regex-scanned its actual code fields (`solution_code`, `buggy_code`, `shuffled_lines`, etc. — whichever present) for concrete Python syntax markers (`.append(`, `.upper(`/`.lower(`, slicing `[a:b]`, list comprehensions, `f"..{...}"`, `len(`, `for x in`, `while`, `if/elif/else`, dict literals/indexing, `int(`/`str(`/`float(`, `def`, boolean keywords, comparison operators, string `+` concatenation, plain assignment).
3. Built a concept -> tier/topic index by reading full `explanation`/`examples` text of every apprentice, journeyman, master, expert, and legend topic and confirming (not just keyword-matching) where each concept is genuinely first taught, e.g. confirmed `.upper()`/`.lower()`/slicing are explicitly introduced in journeyman `string_manipulation` (`"hello world"[0:5]` example), not earlier.
4. Where a challenge exhibits multiple concepts, picked the most advanced/specific one as the 'driving' concept for tier placement (e.g. a challenge doing both assignment and `.append()` maps by `.append()`, since assignment alone is more elementary and already implied).
